# 評測工具 Roadmap

## 批次作答的速度與題間干擾

**待實驗。** 同一組醫學題，哪些後端設定能提高每小時完成題數？把多題放進同一段對話時，模型的答案又有多容易受相鄰題目影響？

目前 `medbench run` 每題以一則獨立訊息送出，設定檔的 `concurrency` 控制同時在途的請求數。既有工具可量測併發吞吐及長前綴快取。醫學題的共同指令通常很短，題幹、病例與選項仍需各自編碼，實際節省的時間要在題庫上量。[執行器](../medbench/runner.py) · [併發測量](../scripts/slot_sweep.py) · [前綴快取測量](../scripts/prefix_cache.py)

| 實驗條件 | 模型作答時看得到什麼 | 要回答的問題 |
|---|---|---|
| 單題依序 | 自己的題幹與選項 | 同一題重跑，答案本來就會變動多少？整份測驗需要多久？ |
| 獨立題目並行 | 每題仍有獨立上下文。支援 continuous batching 的後端可在同一輪 GPU 運算處理多條序列 | 提高併發後，吞吐、延遲及逐題答案如何變化？完全相同的指令前綴可另測冷、暖快取。 |
| 同一提示詞放多題 | 同批的所有題幹與選項，以及在同一回覆中先生成的答案 | 同一道題單獨答、排第一或排最後，換一組相鄰題後是否改答？ |

固定題庫重跑時，可加測 vLLM 離線批次推論，一次提交一串獨立提示詞。支援 token ID 輸入的後端還可以預先分詞，按 tokenizer 版本和對話模板保存結果，先核對與文字路徑產生的 token ID 完全相同。這可省去重複分詞的 CPU 工作，每道新題的輸入仍需由模型讀取。[vLLM 離線批次範例](https://docs.vllm.ai/en/stable/getting_started/quickstart/) · [可接受的輸入格式](https://docs.vllm.ai/en/stable/api/vllm/inputs/llm/)

後端合批與前綴快取分別影響排程及輸入計算。快取命中可省去相同前綴的重算，後續輸出仍需生成。既有批次提示研究可作為組題方法的起點。[Hugging Face continuous batching](https://huggingface.co/docs/transformers/main/en/continuous_batching) · [vLLM 前綴快取](https://docs.vllm.ai/en/stable/features/automatic_prefix_caching/) · [Cheng 等，EMNLP 2023](https://aclanthology.org/2023.emnlp-industry.74/)

### 第一輪怎麼測

1. 固定同一份有審定答案的選擇題、模型與量化版本、推論後端、硬體、提示範本和解碼設定。先重複單題基準，再以相同題目測獨立併發，例如 1、2、4、8。記錄逐題 seed、後端是否支援、冷暖快取及其他服務負載。[vLLM 批次與可重現性](https://docs.vllm.ai/en/v0.31.0/features/batch_invariance/)
2. 多題共用提示詞時，先以相同格式跑每批 1 題作為對照，再試每批 2、4、8 題。固定目標題，輪替首、中、末位置，分別配同科和跨科、長度相近的獨立題。繁中與英文分層。同病例連題、同題翻譯及會提示彼此答案的題目另組。每批記錄題序、批次 seed、上下文長度，按題數配置可比較的輸出預算。
3. 每批回傳題目 ID 與答案，逐題驗證缺答、重複 ID、未知 ID 及截斷，保存原始輸出。現有單題解析器只取最後一個答案。實作時各條件使用獨立執行目錄與提示版本，讓同一題在不同條件下都能評分及續跑。

### 報告指標

- **效率**用相同題集的總牆鐘時間、每小時完成題數、每小時答對題數及 p95 延遲衡量。另記輸入與輸出 token、首 token 時間、峰值顯存，以及後端實際回報的快取命中量。多題共用回覆時，首 token 與完成延遲以整批為單位。
- **題間干擾**以同一目標題配對。答案翻轉率為「選項有變的題數 ÷ 兩條件都能解析的配對題數」，並列配對分母、原本答對後改錯及原本答錯後改對的數量。與同格式單題重跑的翻轉率對照，再按題位、同科或跨科比較。即使總正確率持平，也能看出哪些題互相抵銷。
- **成績與採用條件**以全體目標題計正確率，缺答或無法唯一歸戶的題目計錯，另列缺答與錯配率。第一輪事先訂出可接受的正確率下降及翻轉幅度，再給出配對差與信賴區間。同一批的題目可能一起受影響，估計不確定性時保留整批及重複組題的關係。正式單題分數與共享上下文實驗各自報告。
